## 1. Gap closed by G36

Before G36:
- the registry could discover skills and resolve semantic resource paths;
- execution injected only `prawny-router-v3`, `prawo-polskie-v2` and the selected DR `SKILL.md`;
- three core legal resources were checked for existence, but their content was not actually inserted into the execution context;
- arbitrary corpus instructions such as `view modules/...`, `view references/...`, `view shared/...` or `view <other-skill>/...` had no host-level local read tool.

G36 closes that runtime-access gap.

---

## 2. Actual core-resource reads

`LegalSession` now:
- resolves the mandatory core resources;
- opens them as UTF-8;
- rejects missing, unreadable or empty core resources;
- retains the exact read content for the current execution.

`LexExecutionEngine` injects the actually read core content into the system prompt.

Therefore `resource_read=OK` for the mandatory core resources now corresponds to a real read, not merely a path/existence check.

---

## 3. Local legal corpus tools

Every legal provider session now exposes:
- `list_legal_skills`;
- `list_legal_resources`;
- `read_legal_resource`.

The tools:
- operate only inside the configured Lex corpus root;
- reuse the registry's semantic path resolver;
- block traversal outside the corpus;
- support `modules/`, `references/`, `shared/` and registered cross-skill paths;
- paginate large text resources by character offset;
- record local read/tool decisions in the session audit.

An invalid corpus read causes G36 to block release rather than allowing silent substitution from model memory.

## 5. Important semantic boundary

G36 PASS means:

**the runtime can locally discover and read the entire supported textual legal-skill corpus on demand.**

It does not mean:
- every resource is preloaded into every prompt;
- all 1,187 text resources should be loaded for every matter;
- the model may treat corpus content as proof that current law is unchanged;
- COV/B+ corpus coverage means every provision of Polish law is fully stored locally.

The existing official-source verification and temporal gates remain mandatory for statutory and case-law claims.

## 6. Regression fixes found while integrating G36

The full regression audit caught and fixed:
1. implicit test-provider auto-tool execution after every session gained corpus tools — changed to explicit opt-in for provider conformance tests;
2. a public response regression that overwrote the finalizer's own `DEGRADED` result when another gate blocked release — publication remains blocked, but finalizer status is now preserved accurately;
3. a G34H upload-store robustness issue where a later refactor could leave `secure/incoming` absent — the secure store now creates the validated parent directory before the atomic per-upload directory.

These fixes are included in the validated implementation SHA.
