## Goal

Prevent a pinned G18 source descriptor from being treated as current merely because it exists in the runtime registry.

G19 adds a fresh ELI temporal decision before legal-reference verification.

## Runtime decision

For a base act the checker now:

1. fetches official `/references`;
2. selects the newest relation under `Inf. o tekście jednolitym` whose status is in force;
3. fetches the selected t.j. metadata;
4. fetches references of the selected t.j.;
5. detects amendments promulgated after the t.j. using:
   - base-act `Akty zmieniające` + date comparison;
   - t.j. `Nowelizacje po tekście jednolitym`;
6. merges both amendment channels;
7. compares current t.j. with the G18 pinned descriptor;
8. checks whether the current text is available as HTML or only PDF.

## Fail-closed statuses

- `CURRENT`
- `STALE_CONSOLIDATED_TEXT`
- `POST_TJ_AMENDMENTS`
- `CURRENT_TEXT_REQUIRES_PDF`
- `NO_CURRENT_CONSOLIDATED_TEXT`
- `SOURCE_METADATA_UNAVAILABLE`

Only `CURRENT` is currently permitted to continue to the text verifier.

All other states produce a `TEMPORAL_*` denial before citation verification.

## Production integration

The live local server now constructs `LegalVerificationToolRuntime` with `TemporalSourceFreshnessChecker`.

Therefore:

`provider tool call → act resolver → temporal freshness → ToolBroker → source fetch → ledger → HARD GATE`

A stale descriptor cannot silently fall through to the old pinned URL.
