# Lex Machina 0.1.7 — roadmap wdrożeniowa

Status dokumentu: ACTIVE  
Gałąź robocza: `work/0.1.7-ux-diagnostics-2026-09-21`  
Gałąź wydaniowa: `release/0.1.7`  
PR: #73

## Cel 0.1.7

0.1.7 porządkuje główną architekturę UX, upraszcza zarządzanie modelami i kontami,
zapewnia widoczny stan długich operacji oraz rozszerza nawigację po sprawach i dokumentach.
Zmiany nie mogą osłabić istniejących hard-gate'ów bezpieczeństwa, prywatności ani weryfikacji źródeł.

## Faza 1 — architektura informacji i nawigacja

Status: IMPLEMENTED / VALIDATION IN PROGRESS

- sześć głównych sekcji: Czat, Akta, Skille, Sprawa, Kancelaria, Ustawienia;
- responsywny układ kart bez 5+1 wrap;
- usunięcie nakładających się pływających paneli;
- działania konta przeniesione do stałej nawigacji;
- nagłówki i akcje mogą się bezpiecznie zawijać.

Kryteria akceptacji:
- brak nakładania paneli przy 1366×768, 1024×768 i 390×844;
- wszystkie sekcje są dostępne z klawiatury;
- brak poziomego overflow głównej aplikacji.

## Faza 2 — centrum Ustawień

Status: IMPLEMENTED / VALIDATION IN PROGRESS

Sekcje:
1. Modele i AI;
2. Użytkownicy i uprawnienia;
3. Hasło i bezpieczeństwo;
4. Aplikacja i utrzymanie.

Zakres:
- instalacja/naprawa/uruchamianie/zatrzymywanie/usuwanie lokalnych modeli;
- konfiguracja providerów, kont i kluczy API;
- model pomocniczy;
- globalni użytkownicy;
- uprawnienia bieżącej sprawy;
- zmiana hasła i recovery;
- aktualizacje, runtime, diagnostyka instalacji.

Kryteria akceptacji:
- funkcje nie występują równolegle jako pływające panele;
- role globalne i role sprawy są wyraźnie rozdzielone;
- użytkownik bez ADMIN nie widzi niedozwolonych operacji administracyjnych.

## Faza 3 — dock modelu w Czacie

Status: IMPLEMENTED / VALIDATION IN PROGRESS

- sticky selector providera/modelu;
- uruchomienie modelu lokalnego bez opuszczania Czatu;
- rozróżnienie STOPPED / PROVISIONING / STARTING / READY;
- szczegółowe zarządzanie modelem pozostaje w Ustawieniach.

Kryteria akceptacji:
- READY oznacza aktywny wybrany model, nie tylko działający runtime;
- zmiana providera nie pozostawia nieaktualnego statusu modelu;
- podczas wykonania nie można przypadkowo przełączyć modelu.

## Faza 4 — login i lifecycle hasła

Status: IMPLEMENTED / VALIDATION IN PROGRESS

- nowy ekran logowania i branding zgodny z instalatorem;
- informacja admin/admin tylko gdy `passwordSetupPending=true`;
- po zmianie hasła informacja nie wraca po logout/restart;
- banner hasła prowadzi do Ustawienia → Hasło i bezpieczeństwo.

Kryteria akceptacji:
- regresja bootstrap/change-password/logout/restart;
- brak wyświetlenia admin/admin po zakończeniu setupu.

## Faza 5 — widoczny postęp i diagnostyka

Status: IMPLEMENTED / VALIDATION IN PROGRESS

- licznik czasu wykonania;
- bieżący etap po stronie UI;
- heartbeat lokalnego runtime;
- pełny bezpieczny raport błędu: kod, HTTP, etap/gate, reason, opis, trace;
- redakcja tokenów Bearer, sk-* i API-key-like values.

Kryteria akceptacji:
- długie wykonanie nie wygląda jak zawieszenie aplikacji;
- utrata heartbeat nie jest mylona z błędem modelu;
- diagnostyka nie ujawnia sekretów.

## Faza 6 — wyszukiwanie spraw i dokumentów

Status: IMPLEMENTED / VALIDATION IN PROGRESS

### 6A. Wyszukiwanie spraw
- nazwa i caseId — wdrożone;
- status: aktywna / archiwalna — wdrożone;
- rola w sprawie: OWNER / EDITOR / ANALYST / VIEWER — wdrożone;
- sortowanie: ostatnio zmieniane / najnowsze / nazwa A–Z — wdrożone;
- aktualnie otwarta sprawa nie znika z selektora w sposób powodujący zmianę kontekstu — wdrożone.

### 6B. Wyszukiwanie dokumentów
- nazwa, mediaType, itemId — wdrożone;
- cały workspace bieżącej sprawy — wdrożone;
- wyszukiwanie semantyczne/treściowe przez istniejący case-knowledge index — wdrożone;
- snippet + zakres stron + ścieżka folderu — wdrożone;
- filtr typu dokumentu — wdrożone;
- filtr zakresu: cała sprawa / bieżący folder — wdrożone;
- podgląd PDF otwierany na stronie trafienia — wdrożone;
- degradacja do metadanych, jeśli indeks treści jest niedostępny — wdrożone;
- logika filtrowania wydzielona do `search-filters.ts` i objęta testami regresyjnymi.

Kryteria akceptacji:
- wpisanie frazy nie generuje requestu dla każdego znaku bez debounce;
- błąd indeksu treści nie blokuje filtrowania po metadanych;
- wynik treści prowadzi do właściwego dokumentu i pokazuje kontekst strony.

## Faza 7 — warstwa źródeł II/III rzędu

Status: PARTIAL / DESIGN + HARD-GATE REQUIRED

Obecnie:
- Tier 1: implementacja oficjalnego retrieval + native verification;
- Tier 2A: implementacja szeroka przez federację i ścieżki oficjalne;
- Tier 2B: polityka zdefiniowana, brak generycznego retrievera;
- Tier 3: częściowe research coverage, brak generycznego retrievera web.

Plan:
1. SourceCandidate z provenance i tier;
2. klasyfikacja 2A/2B/3 przed użyciem w odpowiedzi;
3. osobny retrieval dla materiałów pomocniczych;
4. obowiązkowy cross-check tez prawnych z Tier 1/2A;
5. jawna etykieta źródła pomocniczego w evidence;
6. brak możliwości nadania VERIFIED przez źródło 2B/3;
7. audyt coverage i fail-closed dla konfliktu źródeł.

Kryteria akceptacji:
- 2B/3 nigdy nie potwierdza samodzielnie aktualnego brzmienia przepisu;
- 2B/3 nie potwierdza samodzielnie istnienia orzeczenia;
- każda teza oparta pomocniczo na 2B/3 ma provenance i wskazany cross-check.
