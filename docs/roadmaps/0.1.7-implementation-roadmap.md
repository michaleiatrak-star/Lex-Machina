Status dokumentu: ACTIVE

## Cel 0.1.7

0.1.7 porządkuje główną architekturę UX, upraszcza zarządzanie modelami i kontami,
zapewnia widoczny stan długich operacji oraz rozszerza nawigację po sprawach i dokumentach.
Zmiany nie mogą osłabić istniejących hard-gate'ów bezpieczeństwa, prywatności ani weryfikacji źródeł.

## Faza 1 — architektura informacji i nawigacja

Status: IMPLEMENTED / VALIDATION IN PROGRESS

- sześć głównych sekcji: Czat, Akta, Skille, Sprawa, Kancelaria, Ustawienia;
- responsywny układ kart bez 5+1 wrap;
- usunięcie nakładających się pływających paneli;
- działania konta przeniesione do stałej nawigacji;
- nagłówki i akcje mogą się bezpiecznie zawijać.

Kryteria akceptacji:
- brak nakładania paneli przy 1366×768, 1024×768 i 390×844;
- wszystkie sekcje są dostępne z klawiatury;
- brak poziomego overflow głównej aplikacji.

## Faza 7 — warstwa źródeł II/III rzędu

Status: IN IMPLEMENTATION — 7A ENFORCEMENT IMPLEMENTED / 7B RETRIEVER PENDING

Obecnie:
- Tier 1: implementacja oficjalnego retrieval + native verification;
- Tier 2A: implementacja szeroka przez federację i ścieżki oficjalne;
- Tier 2B: polityka zdefiniowana, brak generycznego retrievera;
- Tier 3: częściowe research coverage, brak generycznego retrievera web.

### 7A — polityka, provenance i hard-gate

Status: IMPLEMENTED / VALIDATION IN PROGRESS

- `legal-source-policy.ts`: `LegalSourceCandidate`, tier, provenance, access mode i cross-check status;
- deterministyczna klasyfikacja znanych domen R1/R2A/R2B;
- nieznane domeny klasyfikowane konserwatywnie jako R3 do czasu niezależnego potwierdzenia kryteriów redakcyjnych;
- `VerificationLedger` odrzuca próbę nadania `VERIFIED` lub formalnego `SUPPORTED` źródłom R2B/R3;
- Gate I nie renderuje `✅ [VER]` dla R2B/R3 także w ramach defense-in-depth;
- każdy wynik search/get/call federacji niesie `_lexSourcePolicy` z tier, provenance i `verificationAuthority=LEX_NATIVE_ONLY`;
- lokalny tool `assess_legal_source` ocenia URL, aktualność R3 i stan cross-checku bez pobierania treści;
- `CONFIRMED_R1_R2A` wymaga rzeczywistego URL sklasyfikowanego jako R1 albo R2A;
- konflikty z R1/R2A są fail-closed.

### 7B — bezpieczny retrieval materiałów pomocniczych

Status: PENDING

Plan:
1. osobny retrieval dla materiałów 2B/3 przez kontrolowany kanał egress;
2. SSRF-safe URL/DNS/IP policy (HTTPS, brak credentials, blokada loopback/private/link-local i DNS rebinding);
3. limit rozmiaru/czasu/redirectów i jawny content-type;
4. ekstrakcja daty publikacji/aktualizacji;
5. provenance transportu i hash pobranej treści;
6. automatyczny cross-check tezy prawnej z R1/2A;
7. jawna etykieta „Źródło pomocnicze” w evidence/UI;
8. brak możliwości użycia 2B/3 jako samodzielnej podstawy wniosku.

Kryteria akceptacji:
- 2B/3 nigdy nie potwierdza samodzielnie aktualnego brzmienia przepisu;
- 2B/3 nie potwierdza samodzielnie istnienia orzeczenia;
- każda teza oparta pomocniczo na 2B/3 ma provenance i wskazany cross-check;
- brak cross-checku R1/2A pozostawia materiał wyłącznie jako research lead;
- generic retriever nie jest uznany za wdrożony, dopóki nie ma SSRF-safe egress i testów fail-closed.
